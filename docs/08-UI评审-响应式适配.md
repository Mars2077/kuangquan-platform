| 指标 | 取法 |

## 1. 结论摘要

### 1.1 impeccable audit 评分

| 维度 | 得分 | 依据 |
|---|---|---|
| Accessibility | **2 / 4** | 表单 label 完整、对比度达标；但 3 个 `<canvas>` 无 `role`/`aria-label`，页面从 `<h3>` 起始无 h1/h2，7–27 个交互目标高度仅 16–20px |
| Performance | **3 / 4** | 产物 gzip ≈190 kB、图表 canvas 按需渲染、marker 428 个无明显卡顿；扣分在 `/warehouse` 一次性渲染 40 行资产表 + 13 行专题表且无分页 |
| Theming | **3 / 4** | tokens 体系完整（色/字号/圆角/间距）、无紫色、深色一致；少量组件仍写死 px 尺寸（气泡 49×36） |
| Responsive | **1 / 4** | 全站不可滚动（P0）、大屏 ≤1360px 面板塌成 2px（P0）、宽表格无横向滚动（P1）——「some breakpoints, many failures」 |
| Implementation Integrity | **2 / 4** | `main.shell-main` 是**全站无任何 CSS 规则的空类**；`@media (max-width:1360px)` 与 `.screen-col{padding-bottom:198px}` 相互冲突；表格容器缺少滚动契约 |
| **合计** | **11 / 20** | **Acceptable**（10–13 档：significant work needed） |

> 分数落在 Acceptable，但两个 P0 的实际后果是「手机端和 1280 笔记本上，超过一屏的内容**永久看不到**」，严重度高于分数体现的水平。

### 1.2 三个必须先修的结论

1. **全站不能滚动**：`<main class="shell-main bleed">` 的 `shell-main` 在全部 CSS 中零命中，外层 `.shell` 是 `height:100%;overflow:hidden`。实测 1920×1080 打开 `/warehouse`，`main` 高 **1935px**、可视区 973px，`window.scrollTo(0,600)` 后 `scrollY` 仍为 **0** —— 页面下半部分 962px 内容（资产台账、入库表单）无法到达。
2. **驾驶舱在 1280/1024/768/390 整块崩塌**：`.screen` 变单列后 `.screen-col` 只剩 228px 高，其中 `padding-bottom:198px`（为浮动列表预留）占掉 198px，`flex:1 1 0` 的六块面板被压成 **2px**（实测 `panels:[2,2,2,2,2,2]`）。1280×800 下驾驶舱只剩地图 + 底部列表。
3. **宽表格在窄屏被裁而不是横向滚动**：390×844 下 `/battle` 表格宽 **604px**、`/biz/*/:feature` **582px**、`/system` 卡片 **526px**，容器均为 `overflow:visible`，右侧列被外壳裁掉且无法查看。

### 8.2 三处误判的更正（首轮报告有误，此处更正）

| 原编号 | 首轮结论 | 复测事实 | 处理 |
|---|---|---|---|
| B-02 | 390 下 `/battle` 表格 604px「被裁、四季度列缺失」 | 容器 `.table-wrap` 的 `overflow-x:auto`、`clientWidth 358 < scrollWidth 604`，**可横向滑动**，列不丢失 | 误判，撤销；真问题是同页 `.card` 内直挂表格撑宽，已由 R-03 修 |
