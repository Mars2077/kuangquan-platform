## 二、基础表

### region 行政区划

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | TEXT PK | 行政区划代码（510000 省 / 510100 市 / 330502 区县） |
| name | TEXT | 名称 |
| level | INTEGER | 1=省 2=市 3=区县 |
| parent | TEXT | 上级 code |
| short | TEXT | 简称（成都、彭州） |
| center_lon / center_lat | REAL | 中心点经纬度 |

### sys_user 系统用户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| username / password | TEXT | 登录名 / bcrypt 哈希 |
| name / org / title | TEXT | 姓名 / 单位 / 职务 |
| role | TEXT | admin / province / city / county / enterprise / public |
| region_code / region_name | TEXT | 数据权限范围（前缀匹配） |
| status | TEXT | 正常 / 停用 |
| last_login / created_at | TEXT | 时间戳 |

### sys_dict 数据字典 / audit_log 操作审计

- `sys_dict`：`type`（字典类型）、`code`、`name`、`sort`。
- `audit_log`：`username`、`name`、`action`（登录/新增/修改/删除/流程推进/流程退回/导出…）、`target`、`detail`、`ip`、`created_at`。

## 三、主体业务表

### mine 矿山

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name / enterprise / right_holder | TEXT | 矿山名称 / 企业 / 采矿权人 |
| econ_type | TEXT | 经济类型（有限责任公司等） |
| area_km2 | REAL | 矿区面积（平方千米） |
| license_no | TEXT | 采矿许可证号 `C510000…` |
| mineral | TEXT | 开采矿种 |
| valid_from / valid_to | TEXT | 有效期起止 |
| region_code / region_name / city_code / city_name | TEXT | 行政区划 |
| status / scale / mine_type | TEXT | 生产状态 / 规模（大型…）/ 矿山类型 |
| green_level / digital_level / smart_level | TEXT | 国家级·省级·市级 / 数字矿山 / 智能矿山 |
| devices_total / devices_online | INTEGER | 接入设备数 / 在线数 |
| video_connected / monitor_connected / warn_connected | INTEGER | 视频 / 监测设备 / 监测预警 是否接入（0/1） |

### mineral_deposit 矿产地

`code`、`name`、`region_code`、`region_name`、`city_code`、`mineral`、`stage`（待查/在查/查明/规划）、`scale`、`area`、`reserve_t`（万吨）、`degree`（勘查程度）、`coord`（拐点串）、`lon/lat`、`owner`、`updated_at`。

### mining_right 矿业权

`license_no`、`right_type`（采矿权/探矿权）、`mine_name`、`holder`、`mineral`、`area`、`region_code/region_name/city_code`、`valid_from/valid_to/issue_date`、`status`（有效/注销/抵押…）、`method`（出让方式）、`price`（成交价 万元）、`gdp_type`、`scale`、`lon/lat`、`mine_id`（关联 mine）。

### plan_zone 规划区块

`code`、`name`、`zone_type`（重点勘查区/重点开采区/建筑石料集中开采区…）、`region_code/region_name`、`mineral`、`area`、`reserve_t`、`level`（省/市/县）、`version`、`status`、`updated_at`。

### plan_indicator 规划指标

`region_code/region_name`、`level`、`name`（矿山总数上限/大中型比例/绿色矿山建成率…）、`category`（约束性/预期性）、`unit`、`target`、`actual`、`year`、`warn`（正常/黄色预警/红色预警）。

### reserve_review 储量评审备案

## 四、绿色矿山

### green_apply 申报

`mine_id`、`mine_name`、`region_code/region_name`、`apply_level`（国家级/省级/市级）、`year`、`stage`（企业自评/县级初审/市级核查/省级公示/已入库）、六维分 `score_env/score_develop/score_utilize/score_energy/score_tech/score_manage`、`total_score`、`weak_items`、`submit_at/audit_at/auditor`、`remark`。

### green_out 出库

`mine_id`、`mine_name`、`out_type`（自动出库/手动出库）、`reason`、`trigger_rule`（触发的自动规则）、`apply_by`、`verify_by`、`status`、`occurred_at`。

> 自动出库规则：严重违法违规、较大以上安全事故、突发环境事件、采矿证过期注销、整改逾期未达标、连续两年复核不合格。

## 五、智慧监管

### device 感知设备

`code`、`name`、`device_type`（视频监控/粉尘/噪声/雨量/地下水位/GNSS位移/倾角/地磅…）、`category`、`mine_id`、`mine_name`、`region_code`、`lon/lat`、`status`、`online`（1 在线 / 0 离线）、`last_heartbeat`、`threshold`（阈值描述）、`unit`、`value`（当前值）、`updated_at`。

### alert 预警与线索

`alert_no`、`kind`（状态报警/监测指标报警/越界线索/遥感图斑）、`level`（一级/二级/三级）、`source`（视频AI/遥感/物联感知/人工）、`mine_id`、`mine_name`、`region_code/region_name`、`content`、`value`、`threshold`、`status`（未处置/处置中/已销号）、`occurred_at`、`handled_at`、`handler`、`order_id`。

### work_order 问题处置工单

`order_no`、`source`、`category`、`title`、`mine_id`、`mine_name`、`region_code/region_name`、`level`、`status`（待分派/处理中/待复核/已销号）、`assignee`、`dept`、`found_at`、`due_at`、`closed_at`、`overdue`（0/1 超期标记）、`timeline`（JSON 节点数组）、`content`。

### patrol_log 巡查日志

`plan_name`、`grid`（网格）、`mine_id`、`mine_name`、`region_code`、`inspector`、`sign_at`（定位签到时间）、`lon/lat`、`photos`（照片数）、`finding`、`result`（正常/发现问题/已整改）。

### credit_record 信用记录

`mine_id`、`mine_name`、`region_code/region_name`、`score`、`level`（A/B/C/D）、`punish_count`、`abnormal`（是否异常名录 0/1）、`year`、`list_type`（红名单/正常/关注名单/黑名单）、`detail`（JSON 扣分明细）。

### gov_project 治理工程

`code`、`name`、`category`（生态修复/地灾治理/绿色矿山建设）、`region_code/region_name`、`owner`、`budget`、`paid`、`start_at/end_at`、`status`、`progress`（%）、`nodes`（JSON 节点）。

## 七、专题与通用表

### battle_task 重点任务（作战图）

| 字段 | 说明 |
| --- | --- |
| year | 年度（2022—2026） |
| category | 任务类型（如「地矿共富提质助推行动」） |
| seq | 序号 |
| content | 重点工作内容（同值连续合并展示） |
| outcome | 预期成果 |
| deadline | 完成时限（季度） |
| dept / support_dept | 责任部门 / 支撑部门 |
| q1/q2/q3/q4 | 四季度状态：已完成 / 推进中 / 延后 / 未完成（决定旗帜颜色） |
| status | 汇总状态 |

### biz_record 通用业务台账（服务 26 个功能点）

| 字段 | 说明 |
| --- | --- |
| feature | 功能点标识（如 `rights-clean-sale`），用于分区 |
| code / title | 编号 / 标题 |
| status / stage | 办理状态 / 当前环节（流程字段） |
| region_code / region_name | 区划 |
| mineral / applicant / dept | 矿种 / 申请人 / 承办部门 |
| amount / qty | 金额（万元）/ 数量（万吨等） |
| occur_at / due_at | 发生/受理时间、办理期限 |
| level / remark | 级别 / 备注 |
| payload | JSON，功能点专属扩展字段（如 `land/forest/env/safe/nodes_done`） |
| history | JSON 数组，流程轨迹 `[{step,at,by,action,comment}]` |
| created_by / created_at / updated_at | 审计字段 |

> 为什么用单表承载 26 个流程类功能点：这些功能点共享「编号—标题—区划—环节—状态—时限」骨架，差异只在少量扩展字段；用 `feature` 分区 + `payload` 扩展，避免 26 张同构表，也让通用 CRUD/流程/导出/统计只写一份。

### data_catalog / data_asset 数据仓

- `data_catalog`：`topic`（地质勘查/储量备案/开发利用年报/在采矿山）、`name`、`category`、`source`、`rows`（记录数）、`unit`、`updated_at`、`fields`（JSON 字段说明数组）。
- `data_asset`：`topic`、`name`、`file_type`、`size_kb`、`source`、`year`、`region_name`、`uploaded_at`、`meta`（JSON：storedAs / uploader / note）。

## 八、索引与约束说明

- 主键均为自增 `id`（`region` 用 `code`）。
- 未启用外键（`PRAGMA foreign_keys = OFF`），关联靠业务字段（`mine_id`、`region_code`、`feature`），便于演示数据重灌与分库迁移。
- 建议在生产数据增长后补充索引：

```sql
CREATE INDEX idx_mine_region   ON mine(region_code);
CREATE INDEX idx_right_region  ON mining_right(region_code);
CREATE INDEX idx_dep_region    ON mineral_deposit(region_code);
CREATE INDEX idx_biz_feature   ON biz_record(feature, region_code);
CREATE INDEX idx_alert_status  ON alert(status, occurred_at);
CREATE INDEX idx_order_status  ON work_order(status, due_at);
```

- 枚举值（状态、级别、类型）统一存中文，前端直接展示；如需国际化再引入 `sys_dict` 映射。
