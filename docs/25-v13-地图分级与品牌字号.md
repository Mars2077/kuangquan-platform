# v13 · 地图分级显示、数据仓入图、品牌与字号统一

> 本轮对应需求：地图按缩放级别显示点位/规划区；数据仓的图件与三维模型要能在地图中展示；系统名称统一为「绿矿智用」并去掉「省域空间」「四川省」，整体字调大且层级统一；登录页左侧只留系统名称。

## 1. 地图缩放分级（第 1 条）

### 改前
- 所有点位、气泡、规划区块一次性全画：省级视角 428 个矿点 + 21 个市州气泡堆在一起，视觉噪音大；
- 缩放到城市级别时反而看不到规划区块（`plan_zone` 没有坐标列，图层接口只返回属性）。

### 改后

| 缩放级别 | 可见内容 | 说明 |
|---|---|---|
| < 8 级 | 仅聚合气泡（市州/区县 + 数量） | 省级视角先看总量 |
| ≥ 8 级 | 气泡 + 具体点位（矿山/矿产地/矿业权/隐患点，按专题） | 一个点位一个 `CircleMarker` |
| ≥ 10 级 | 气泡 + 点位 + 规划区块标注 | 菱形 + 区块名，按类型着色 |

- 判定在 `web/src/components/GeoMap.jsx` 的覆盖物 effect 内：
  `const showPoints = zoomRef.current >= 8; const showZones = zoomRef.current >= 10;`
  依赖数组含 `zoomTick`，`zoomend` 时 `setZoomTick(n => n + 1)` 触发重建。
- 新增 `onZoom` 回调，驾驶舱据此显示提示条（`.map-zoom-hint`，地图左下，`role="status"`）：
  - `第 6.9 级 · 仅显示数量，放大到第 8 级查看点位`
  - `第 8.6 级 · 已显示具体点位`
  - `第 11.4 级 · 已叠加规划区块与具体点位`
- 规划区块颜色：重点勘查区 `#ffcc44`、重点开采区 `#ff8a3d`、砂石土料集中开采区 `#49c3ff`。

### 后端配套（真实数据，不造坐标）
`plan_zone` 表只有 `region_name`，没有经纬度。`server/src/routes/dashboard.js` 的 `topo` 图层改为：

```sql
SELECT p.id, p.name, p.region_name, p.zone_type, p.area,
       ROUND(r.center_lon + ((p.id % 17) - 8) * 0.028, 5) AS lon,
       ROUND(r.center_lat + ((p.id % 13) - 6) * 0.022, 5) AS lat
  FROM plan_zone p LEFT JOIN region r ON r.name = p.region_name
 WHERE 1=1 <行政区划过滤> LIMIT 400
```

即：用所属市州中心点 + 按 `id` 的确定性偏移散开，避免同类区块完全重叠。**只影响展示落点，不改变分区面积、类型、归属等业务属性**；真实部署应替换为分区矢量面。

### 实测
| zoom | 点位覆盖物 | 气泡 | 规划区块 |
|---|---|---|---|
| 6.87 | 0 | 21 | 0 |
| 9.20 | 428 | 21 | 0 |
| 11.40 | 428 | 21 | 400 |

（点位用 `map.getAllOverlays()` 按构造类型统计，`CircleMarker` 走 canvas 渲染，不产生 DOM。）

## 2. 数据仓资产入图（第 2 条）

### 改前
数据仓只有编目与资产台账两张表，图件、模型与地图之间没有入口。

### 改后
资产台账新增「地图」列（`web/src/pages/Warehouse.jsx`）：

- 专题库 → 地图载体的映射（只映射系统里已存在的专题图层，不虚构）：

| 专题库 | 目标场景 | 图层 | 说明 |
|---|---|---|---|
| 地质勘查专题库 | `/scene/geology` | `deposit` | 矿产地载体图层 |
| 储量评审备案范围专题库 | `/scene/deposit` | `deposit` | 矿产地载体图层 |
| 矿山开发利用统计年报专题库 | `/scene/dashboard` | `online` | 在线矿山图层 |
| 在采矿山专题库 | `/scene/dashboard` | `online` | 在线矿山图层 |

- 仅 `矢量 / 栅格 / 三维` 三类资产显示「地图查看」按钮，点击跳
  `/scene/<scene>?layer=<theme>&focus=<资产所属区划>`；
- `三维` 资产额外给一枚立方体按钮，打开「三维矿山模型示意」弹窗：等轴测矿山模型 + GNSS/雨量/摄像头点位示意 + 台账字段（名称、专题库、类型、大小、年度、空间范围、入库时间），并明确标注「演示环境无三维引擎，示意不代表真实几何精度」。

### 驾驶舱承接参数
`web/src/pages/Cockpit.jsx` 新增 `?layer=<theme>&focus=<区划名>` 解析：
- `layer` 命中 `THEMES` 即切换专题图层；
- `focus` 在 `/api/meta/regions` 的 205 条区划里按 `name/short` 匹配后设为当前辖区。

> 修过一个真实缺陷：最初把「已应用」去重键放在 effect 顶部，首帧 regions 还没到就被记成已应用，导致只切图层、不聚焦区划。现在图层立即应用、区划等数据到位后再匹配，且只在匹配成功时写去重键。实测 `#/scene/deposit?layer=deposit&focus=泸州市` → 地图中心 `105.76, 28.49`、zoom 9.21、面板为矿产地六块。

### 需要说明的缺口（不臆造）
`data_catalog` 现有 13 条编目里**没有「规划图件」条目**（只有地勘报告、钻孔柱状图、物化探成果、资金明细、储量备案边界/块段台账/增减序列、开发利用年报/季报/三率、采矿权台账/感知设备/三维模型底座）。因此：

- 数据仓侧只做了「已有资产 → 地图」；
- 规划成果仍通过「保护与规划」模块的专题图层呈现（`topo` 图层，本轮已可在 10 级看到）；
- 若要「规划图件」成为数据仓可入库、可上图的一类资产，需要业务方确认编目口径后再加，属**待补充**项。
