# 驾驶舱 Tab 化与业务中枢流程图（v7）

> 两项改动：①矿产地 / 保护与规划 / 矿业权 / 绿色矿山 / 智慧监管 / 数智地勘 六个专题从「二级页面」收进数字驾驶舱，用 Tab 切换；②业务中枢内按模块输出「业务流程图」，节点可点击进入详情。
>
> 只改界面层：40 个功能点、7 个驾驶舱场景、接口与业务规则均未变。

## 一、驾驶舱 Tab 化

### 1.1 改前

| 项 | 改前 |
| --- | --- |
| 路由 | `/dashboard` + 6 个 `/scene/:scene`（deposit、plan、rights、green、supervise、geology） |
| 顶部导航 | 7 个并列场景链接（首页驾驶舱 + 6 专题），占满导航区 |
| 切换方式 | 点击导航 → 整页路由跳转 → 重新挂载驾驶舱组件 |

### 1.2 改后

| 项 | 改后 |
| --- | --- |
| Tab 位置 | 顶栏下一行（40px）：综合总览 / 矿产地 / 保护与规划 / 矿业权 / 绿色矿山 / 智慧监管 / 数智地勘 |
| 切换方式 | 页内 `setScene()`，不跳路由、不重挂载；面板、地图专题、底部列表、详情落点随之切换 |
| 顶部导航 | 收敛为「数字驾驶舱 / 重点任务 | 业务中枢 / 数据仓 / 移动端 / 系统」 |
| 深链兼容 | `/scene/:scene` 保留：进入后自动激活对应 Tab（见 1.4 实测） |
| 尺寸 | 视口高度减去 60（顶栏）+ 40（Tab）；1920×1080 下 `.dash` 高 980 |

实现要点：

- `web/src/pages/Cockpit.jsx` 新增 `SCENE_TABS` 常量（7 项）与 `const [scene, setScene] = useState(routeScene)`；`routeScene` 仍取 `sceneKey || params.scene || 'dashboard'`，因此旧链接可用。
- Tab 切换时重置选中要素、矿产地勘查程度筛选与测量状态，避免跨专题残留。
- `web/src/layout/Shell.jsx` 删除场景循环渲染，改为固定链接；`SCENE_ROUTES` 保留导出（防止外部引用断裂）。
- `web/src/styles/pages.css` 追加 `.dash-wrap` / `.dash-tabs` / `.dash-tab`（选中态 2px 青色下划线 + 发光，宽度超出时横向滚动，不换行）。

### 1.3 为什么 Tab 而不是继续用路由

六个专题共用同一套「左中右三栏 + 地图 + 底部列表」框架，只是数据源（`/api/screen/:scene`）与面板配置不同。拆成 7 个路由会导致组件反复挂载、地图重复初始化（AMap 实例销毁重建，首屏每次都要等瓦片），且用户无法在同一屏内横向对比。Tab 化后切换只换数据，地图与布局保持，切换体感从「跳页」变成「切视图」。

### 1.4 实测

| 场景 | 结果 |
| --- | --- |
| `/dashboard` | 7 个 Tab 渲染，默认「综合总览」；面板 6 块（矿产资源储量 / 规划与保护 / 矿业权 / 地质勘查 / 绿色矿山 / 智慧监管）；`scrollWidth=1920` |
| 点击「矿业权」Tab | 面板切换为 矿业权结构 / 登记状态 / 规模结构 / 出让方式 / 矿种 Top6 / 出让收益；`.dash-tab.is-on` 唯一 |
| `/scene/green` 直达 | Tab 自动激活「绿色矿山」，面板 绿色矿山分级 / 名录结构 / 六维平均得分 / 申报进度 / 出库情况 / 评价结果 |
| 390×844 | Tab 条可横向滚动（可视 366，内容 518），地图置顶、面板单列，`scrollWidth=390` |

截图：`docs/shots/v7-tabs-dashboard.png`、`docs/shots/v7-tabs-rights.png`、`docs/shots/v7-390-dashboard.png`。

## 二、业务中枢流程图

### 2.1 设计

- 位置：业务中枢左侧卡片内、「模块 Tab + 搜索」之下、台账表格之上。
- 结构：一条泳道 = 一个业务域；泳道内节点 = 该域的功能点，按 `server/src/features.js` 中的既有顺序排列（业务顺序由功能设计文档决定，本轮未重排、未新增）。
- 节点内容：序号、功能点名称、记录数，带流程的功能点追加「N 环节」；有流程的节点描边更亮，用于区分「流程型」与「台账/分析型」。
- 交互：点击节点 → `/hub/:module/:feature`（统一详情页）；节点之间用箭头连接表示推进方向。
- 过滤联动：模块 Tab 与搜索框同时作用于泳道（选「矿业权管理」只出该域泳道；搜索「储量」只剩含该词的功能点）。
- 高度：流程图区固定 322px（≤1100px 为 268px），内部纵向滚动，泳道标题吸顶；表格区独立滚动，页面不整体滚动。

### 2.2 为什么放在中枢而不是驾驶舱

用户诉求是「在业务中枢中，不同模块的业务用流程图展示」。中枢的定位是「按功能点组织」，天生适合用流程表达「一个业务域里有哪些功能、按什么顺序推进」；驾驶舱按专题组织，节点应是空间要素而非功能点。

### 2.3 实测

| 检查 | 结果 |
| --- | --- |
| 全部模块 | 6 条泳道、40 个节点，泳道标题依次为 矿产地智能管理 / 保护与规划管理 / 矿业权管理 / 绿色矿山管理 / 矿产资源智慧监管 / 数智地勘管理 |
| 单模块过滤 | 选「矿业权管理」→ 1 条泳道、12 个节点，流程区 322px 正好容纳 |
| 节点点击 | 点第 2 个节点 → `#/hub/rights/rights-clean-sale`，h1「净矿出让」，详情页流程条 4 个环节 |
| 布局 | `.flow-map` 322px、表格区 395px，`scrollWidth=1920`，页面无整体滚动 |
| 390×844 | 流程图区 268px，6 条泳道 / 40 节点仍可纵向滚动，`scrollWidth=390` |

截图：`docs/shots/v7-hub-flow.png`、`docs/shots/v7-hub-flow-rights.png`、`docs/shots/v7-390-hub.png`。

## 四、已知取舍

1. 六个专题的路由仍然存在（`/scene/*`），只是不再出现在导航里；保留是为了旧链接与书签可用。若要彻底移除，需同步 `docs/03` 路由表与部署说明。
2. 流程图的节点顺序沿用 `features.js` 的定义顺序，不是「跨功能点的业务主流程」。跨域主流程（如「规划→出让→登记」）需要业务方给出权威环节定义，本轮未编造（见第五项待补充）。
3. 全部模块视图下流程图需要纵向滚动才能看全 6 条泳道；单模块视图可一屏看完。

## 五、待补充

1. **跨功能点的业务主流程**：本轮流程图表达的是「域内功能点集合 + 推进方向」，若需要「规划编制 → 区块出让 → 登记发证」这类跨域主流程，需要业务方提供权威的环节名称与顺序，我再按真实链路绘制。
2. **节点状态着色**：当前节点只用描边区分「流程型 / 台账型」，未按「在办 / 办结 / 超期」着色；如需，需先确认状态口径与取数规则（现有字段：`status`、`stage`、`due_at`）。
