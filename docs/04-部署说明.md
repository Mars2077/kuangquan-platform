# 04 · 部署说明

> 本系统为「Node 单进程 + SQLite 单文件」，**不需要独立数据库服务**，部署面极窄。
> 提供三条路径：本地直跑 / Docker / 火山引擎（ECS 源站 + 全站加速 IGA）。

---

## 一、本地与内网部署

### 1.1 直接运行（推荐用于验收）

```bash
npm run setup        # 安装前后端依赖
npm run build        # 构建前端 → web/dist
npm start            # 启动 API + 静态托管，默认 8787
```

浏览器访问 `http://<服务器IP>:8787/`。

环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 服务端口 |
| `JWT_SECRET` | 内置默认值 | **生产必须覆盖** |
| `DB_FILE` | `server/data/kuangquan.db` | 数据文件路径 |

### 1.2 使用 PM2 常驻

```bash
npm i -g pm2
pm2 start server/src/index.js --name kuangquan --cwd server -- --env
pm2 save && pm2 startup
```

### 1.3 系统要求

| 项 | 最低 | 建议 |
| --- | --- | --- |
| Node.js | 22.0（必须，依赖 `node:sqlite`） | 22 LTS |
| 内存 | 512 MB | 2 GB |
| 磁盘 | 1 GB | 20 GB（含上传资产） |
| 系统 | Linux x64 / Windows Server | Ubuntu 22.04 |

## 二、Docker 部署

```bash
docker build -t kuangquan-platform:1.0 .
docker run -d --name kuangquan \
  -p 8787:8787 \
  -e JWT_SECRET='请替换为随机字符串' \
  -v $(pwd)/data:/app/server/data \
  kuangquan-platform:1.0
```

- 数据持久化：挂载 `/app/server/data`（含 `kuangquan.db`、`uploads/`）。
- 也可用 compose：`docker compose up -d --build`。
- 首次启动若无数据文件会自动建表；如需演示数据：`docker exec -it kuangquan node src/seed.js --force`。

## 三、反向代理（可选，推荐给正式域名）

单端口模式下可直连 8787；若需 80/443 + 域名，用 Nginx：

```nginx
server {
    listen 80;
    server_name kuangquan.example.com;

    # 静态资源长缓存（带 hash）
    location /assets/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 接口与页面不缓存
    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;
        client_max_body_size 50m;   # 数据仓文件上传
    }
}
```

> 前端使用 HashRouter（`/#/dashboard`），**无需** history 回退规则；服务端已内置 SPA fallback。

## 四、火山引擎部署（ECS 源站 + 全站加速 IGA）

> 全站加速（IGA / DCDN）负责边缘分发与动态加速，源站仍是跑在本系统上的 Node 服务。
> 若账号下尚未开通，请先在控制台开通「全站加速」并完成实名与域名备案（境内域名需 ICP 备案）。

### 4.1 第一步：部署源站（ECS）

1. 购买 ECS（Ubuntu 22.04，2 vCPU / 4 GB 起），安全组放行 **22、80、443**（8787 仅内网或临时放行）。
2. 安装 Node 22：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v   # 需 ≥ 22
```

3. 拉取代码并启动：

```bash
git clone <仓库地址> /opt/kuangquan && cd /opt/kuangquan
npm run setup && npm run build
JWT_SECRET='<随机串>' PORT=8787 npm start
```

4. 用 PM2 或 systemd 常驻，并用 Nginx 反代到 80/443（见第三节）。
5. 自检：`curl http://127.0.0.1:8787/api/health` 应返回 `{"code":0,...}`。

### 4.2 第二步：在火山引擎控制台配置全站加速

| 步骤 | 配置项 | 建议值 |
| --- | --- | --- |
| 1. 添加域名 | 加速域名 | `kuangquan.<你的域名>`（需已备案） |
| 2. 源站配置 | 源站类型 | IP / 域名（填 ECS 公网 IP 或 Nginx 域名） |
|  | 源站端口 | `80`（若直连 Node 则 `8787`） |
|  | 回源协议 | HTTP 或 HTTPS（与源站一致） |
| 3. 缓存配置 | `/assets/*` | 缓存 30 天，忽略参数 |
|  | `/geo/*`、`*.png/jpg/svg` | 缓存 7 天 |
|  | `/api/*` | **不缓存**（动态回源） |
|  | `/` 与 `/#/*` | 不缓存 |
| 4. HTTPS | 证书 | 上传证书或使用免费证书，开启 HTTP→HTTPS 跳转 |
| 5. 接入 | CNAME | 按控制台给的 CNAME 到域名解析 |
| 6. 验证 | 访问 | `https://kuangquan.<你的域名>/#/dashboard` 正常登录即成功 |

要点：

- **接口路径必须排除缓存**，否则登录态与台账数据会被边缘缓存污染。
- 文件上传（数据仓）需在加速域名的「回源请求配置」中放开 `client_max_body_size`，或上传走源站直连。
- 若开启「动态加速」，建议只对 `/api/*` 开启，静态资源走普通缓存即可。

### 4.3 第三步：验收清单

| 检查项 | 期望 |
| --- | --- |
| `https://<加速域名>/api/health` | `{"code":0,"data":{"scenes":7,"modules":6}}` |
| 登录 `admin/admin123` | 进入数字驾驶舱（`/#/dashboard`） |
| 刷新任意业务页 | 不出现 404（HashRouter，天然安全） |
| 驾驶舱地图 | 行政边界与气泡正常显示（`/geo/*.json` 可缓存） |
| 导出台账 | 下载 xlsx 正常（走 `/api/biz/*/export`，不缓存） |

## 五、火山引擎 IGA Pages 静态部署（已上线，无需源站）

全站加速 IGA Pages 的构建管线只接受**客户端渲染（CSR）静态站点**，不接受常驻 Node 进程。
本项目为此提供第二种形态：把数据与业务逻辑下沉到浏览器（`web/src/demo/engine.js`），
构建产物是一组纯静态文件，可直接托管在 IGA Pages / OSS / Nginx 上。

### 5.1 已部署实例

| --- | --- |
| 项目 ID | `541ysnljv4` |
| 部署 ID | `of7xvxhbmy` |
| 访问地址 | <https://kuangquan-platfo-541ysnljv4-tjuhv788ln.preview.iga-pages.com?iga_token=4f406ee8ba6367d152c6cd913eb687e0&iga_time=1795158507> |
| 控制台 | <https://console.volcengine.com/dcdn/pages/detail/541ysnljv4/deploy/of7xvxhbmy> |
| 构建配置 | `web/iga.json`：`buildCommand=npm run build:demo`、`outputDirectory=dist` |

> 预览域名的 `iga_token` 由 CLI 签发、有有效期。需要**长期公开访问**时，在控制台「项目 › 域名管理」绑定自有域名
> （境内域名需 ICP 备案），或在任何时候重新取一次有效链接：
> `cd web && iga pages preview kuangquan-platform`。

### 5.2 部署步骤

```bash
npm install -g @iga-pages/cli     # 已装可跳过
iga login --remote                # 设备码授权；浏览器打开提示的 URL 输入验证码即可
npm run export:snapshot           # 从 SQLite 导出快照 → web/public/demo/data.json，并同步功能规格
cd web && iga pages deploy --name kuangquan-platform -l
```

`deploy` 会自动上传源码、在云端执行 `npm install` + `npm run build:demo`，随后给出 Preview URL 与控制台链接。

### 5.3 静态形态的边界（验收时须知）

| 能力 | 静态版表现 |
| --- | --- |
| 登录、三级数据权限 | 完整支持（账号与角色来自快照，密码仍校验演示口令） |
| 驾驶舱、专题图层、作战图、一矿一档、数据仓、移动端、系统管理 | 完整支持，数据来自构建时快照 |
| 台账增删改、流程流转、导出 Excel/CSV、储量核算、叠置测算、合规预检、评分 | 完整支持；写操作落浏览器 `localStorage`（键 `kq_demo_journal_v1`） |
| 多用户/跨设备共享写入 | **不支持**，各浏览器数据独立；需共享写请用「一/二/三」节的服务端形态 |
| 数据仓文件上传 | 仅记录元数据，不真实落盘 |

### 5.4 v2 演示版新增依赖：高德地图 Key 白名单

v2 起底图改为高德地图 JS API（Key 与安全密钥写在 `web/src/components/GeoMap.jsx` 顶部常量）。**部署到任何域名后都必须做这一步，否则地图会静默降级为本地矢量底图：**

1. 打开高德开放平台控制台 → 应用管理 → 我的应用 → 选中对应 Key → 设置；
2. 在「域名白名单」中加入实际访问域名（协议可省略），例如：
   - 正式域名：`your-domain.com`
   - IGA Pages 预览域：`*.preview.iga-pages.com`
   - 本地调试：`127.0.0.1`、`localhost`
3. 保存后 1–5 分钟生效；验证方式：驾驶舱地图出现卫星/路网底图与「高德地图」字样即成功，若仍是深蓝矢量块状地图则说明降级已发生（功能不受影响，但演示效果变差）。
4. 安全密钥（`securityJsCode`）必须随页面下发，若担心泄露，可在高德控制台改用「代理服务器」方式并配置 `serviceHost`。

其余部署步骤（本地 / Docker / Nginx / ECS + IGA / IGA Pages 静态）与改造前一致。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `node:sqlite` 不存在 | Node < 22 | 升级到 Node 22+ |
| 页面空白、控制台 404 `/api/...` | 只起了前端没起后端 | `npm run dev` 同时起；或 `npm start` 单端口 |
| 台账全部 500 | 数据文件损坏 | 删除 `server/data/kuangquan.db` 重启自动重建 |
| 地图空白 | `web/public/geo` 缺失 | 执行 `node scripts/prepare-geo.mjs` 重新生成 |
| 上传失败 | 反向代理体积限制 | 调整 `client_max_body_size` |
| 加速域名访问报 403 | 缓存了 `/api` 或未备案 | 检查缓存规则与备案状态 |
| 静态版新建的数据不见了 | 换了浏览器/清了站点数据 | 静态版写入存在 `localStorage`，需跨端共享请用服务端形态 |
