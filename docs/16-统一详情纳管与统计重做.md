# 16 · 统一详情纳管（业务中枢）与侧栏统计重做

> 目标：把散落在 6 个业务域、40 个功能点里的「详情」收进同一个模块，用统一入口 / 统一列表 / 统一页面框架 / 统一命名规范管理；并让业务流程在界面上可见（当前环节与上下游）；同时逐模块重做侧边统计区，用数量、结构占比、TopN、达成率等真实口径填满，不再大面积留白。
> 约束：所有指标都来自 `server/data/kuangquan.db` 的真实字段，口径未改动；原文缺失的信息标「待补充」，不编造。

**改造前存在的问题**

1. **v4 及更早版本所有面板统一跳「矿产地智能管理」**（`/biz/deposit/deposit-overview`），与面板语义无关；v5 虽已按语义分流，但落点仍是 6 个业务域里各自为政的孤立页面。
2. **详情页彼此孤立**：`FeaturePage` 只按「当前功能点」渲染 KPI + 筛选 + 表格 + 行操作，页面之间没有横向导航，无法从「储量评审备案」跳到「矿产地清查」。
3. **没有统一入口**：只有顶栏 7 个场景，进详情必须先想「这块面板属于哪个业务域、哪个功能点」。
4. **业务流程不可见**：15 个流程型功能点，列表里只看到 `status` 文字与「办理」按钮，看不出当前处在哪个环节、上下游是什么。

## 2. 统一纳管设计：业务中枢

### 2.1 入口与路由

| 项 | 设计 |
| --- | --- |
| 统一入口 | 顶栏「业务中枢」→ `/hub` |
| 统一列表 | `/hub` 左栏：40 个功能点 × 6 列（所属模块 / 功能点 / 承载数据表 / 记录数 / 流程环节 / 操作），模块 Tab + 关键词搜索 |
| 统一详情 | `/hub/:module/:feature`（复用 `FeaturePage`，`hub` 模式） |
| 命名规范 | 路由 `/{层}/{模块 key}/{功能点 key}`，与 `server/src/features.js` 的 key 完全一致，不再出现「同一功能两种路径」 |
| 兼容 | 原 `/biz/:module`、`/biz/:module/:feature` 保留可访问，不破坏既有链接 |

### 2.2 统一页面框架

```
业务中枢 · 统一详情                       [返回数字驾驶舱]
┌ KPI：纳管功能点 / 流程型 / 承载数据表 / 台账记录 ─────────────┐
├───────────────────────────────┬──────────────────────────────┤
│ 模块 Tab + 搜索               │ 业务流程                      │
│ 40 行功能点表（选中高亮）      │ ① 环节 N 记录数  [当前集中]   │
│                               │ ② 环节 N 记录数               │
│                               │ … 流程记录 / 未落环节 / 数据表 │
│                               │ [进入详情视图]                │
└───────────────────────────────┴──────────────────────────────┘
```

详情页在统一框架上追加一条 **业务流程条**（仅 15 个流程型功能点渲染）：序号 / 环节名 / 该环节记录数 / 承办角色，记录数最多者标 `is-on`，并给出「未落环节」计数。

### 2.3 新增接口

`GET /api/hub/overview?code=` → `server/src/routes/hub.js`

```json
{ "totals": { "features": 40, "workflowFeatures": 15, "tables": 20, "records": 7007 },
  "modules": [ { "key": "deposit", "name": "矿产地智能管理",
    "features": [ { "key": "deposit-survey", "table": "biz_record", "count": 38,
      "steps": [ { "key": "县级填报", "role": "county", "count": 13 }, … ], "other": 0 } ] } ] }
```

口径：`count` 按登录用户的行政区划前缀做三级隔离；流程型走 `biz_record` 且加 `feature = '<key>'` 条件，环节取 `stage`（无 `stage` 列则取 `status`）。

## 4. 侧栏统计重做（逐场景，1920×1080 实测）

所有面板均「每侧 3 块」，`main` 高度恒 1020、`scrollWidth` 恒 1920，无留白塌陷。

| 场景 | 左栏 3 块 | 右栏 3 块 | 实测值（四川省全省） |
| --- | --- | --- | --- |
| dashboard | 矿产资源储量 / 规划与保护 / 矿业权 | 地质勘查 / 绿色矿山 / 智慧监管 | 6 块（沿用） |
| deposit | 勘查程度（环）/ 矿种分布 / 规模结构 | 勘查阶段 / 资源家底 / 资源量 Top5 | 查明 190、在查 91、待查 40、规划 25；大型/中型 122、小型 102 |

| rights | 矿业权结构（环 558）/ 登记状态 / 规模结构 | 出让方式 / 矿种 Top6 / 出让收益 | 累计价款、单宗均价、有效 558 宗 |
| green | 绿色矿山分级（环）/ 名录结构 / 六维平均得分 | 申报进度 / 出库情况 / 评价结果 | 出库 18 家（自动 9 / 手动 9）；六维均分来自 `green_apply` |
| supervise | 预警类型（环）/ 感知设备 / 设备类型 Top6 | 问题处置 / 督办与处置 / 预警等级 | 设备 1548 台，含在线数与在线率 |
| geology | 地勘项目（环）/ 找矿成果 / 项目状态 | 地灾隐患点 / 隐患等级 / 农业地质 | 隐患 140 处；地块 90 宗 |

**口径说明（未改动原有业务含义）**

- 结构类：`COUNT(*) GROUP BY 维度`，占比 = 该值 / 同维度合计 × 100，保留 1 位小数。
- TopN：按计数降序取前 5～6 项，不补零、不合成「其他」。
- 达成率：`actual / target × 100`，仅取 `target > 0` 的指标（`plan_indicator`）。
- 均价：`SUM(price) / 有效宗数`，仅在有价款的矿业权上计算。
- 率类（在线率 / 入库率 / 销号率）：分子分母均取自同一过滤条件下的计数，不做跨期外推。
- **同比 / 环比**：数据库只保留当期快照，除首页驾驶舱已有的同比字段外，其余模块**无法给出真实环比**，本轮不构造；如需，须先补历史快照（标注：待补充）。
